Cell syntax (do not change; the parser depends on it):
- Test artifact: `` `relative/path.test.ts :: exact it/describe title` `` (path relative to the app root; title must occur verbatim in that file).
- Gate artifact: `` `gate-lN.json#checks_key` `` (key must exist under `checks` in `evidence/gate-lN.json`).
- Status is exactly one of `COVERED by test`, `COVERED by live gate`, `GAP`. A row that has both a test and a gate says `COVERED by test` or `COVERED by live gate` for whichever is the primary proof, and the other artifact is supplementary. `GAP` rows carry no artifact for the uncovered part.
- Live gates (`npm run gate -- lN`) hit the deployed site and VMs. They were NOT re-run here. The evidence files record when they last ran (all `pass: true`; gate-l1 at 2026-11-08T06:09Z, l2 to l7 at 2026-11-07).

## Gaps

- **GAP-1 (AC-ALL-1):** no test, gate or evidence file asserts that every verdict row shown in the UI maps to a decision id in the store written by the engine path. The only related code is `card()` in `apps/range-api/src/run.ts`, which builds a card from a stored decision row (comment cites AC-ALL-1), and `apps/broker/test/decision-ids.test.ts` (checks `vultr_ids` on stored rows, not the card-to-store mapping). Needs a new range-api test that feeds rows through `card()`/`publishRecent` and asserts each emitted `decision_id` equals a stored decision id.

Partial coverage inside rows marked COVERED (stated so the table does not overclaim):
- AC-ALL-2: the "runtime log check" half has no artifact. Only the source-grep half and the engine `egress-allowlist` floor rule are tested. The broker-wide "all outbound hosts are in the allow-list" is covered by the engine rule and the boundary lint, not by a log scan.
- AC-L1-3: the decoy-secret test that walks `/proc/*/environ` and the filesystem exists but only runs with `PLB_DOCKER_TESTS=1` and Docker; offline it skipped. The live proof is `gate-l1.json#sandbox_env_clean`.
- AC-L2-3: no test asserts the literal state string `SANDBOX_DESTROYED`; `runner.test.ts` asserts `destroyed === true` after `SANDBOX_TIMEOUT`. `gate-l2.json#runaway_destroyed` is the live check.
- AC-L2-4: the "static check" half is approximated by the boundary lint (no adapter client outside the adapter), not by a dedicated static call-graph check.
- AC-L3-1, AC-L4-1, AC-L5-1, AC-L6-1: the live criterion (real VMs, real Vultr, real S3, TTL + 60 s timing) is proven only by the evidence files from the last live gate run, not re-run here.
