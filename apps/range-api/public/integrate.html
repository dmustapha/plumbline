The contract between an agent and the broker

An agent integrates by sending its cloud actions to the broker instead of to Vultr. The broker answers every request with a decision. Nothing else in the agent needs to change.

Today: the bundled operator (a planner and an executor model on Vultr Serverless Inference) is the agent. To use your own agent, make its cloud calls through the route below. There is no packaged SDK or MCP server yet; that is the next layer.

The request

POST /v1/call
Authorization: Bearer <task token>
Content-Type: application/json

{ "verb": "delete", "class": "instance", "target": { "id": "<instance id>" }, "params": {} }
  • The task token is minted by the broker for one task, expires after 120 seconds, and is revoked for everyone when the kill switch is engaged.
  • verb and class must be a known pair (see Concepts). An unknown pair is refused with ARGS_INVALID.
  • target.id may contain only safe characters. Labels, tags or owners you send are ignored: the broker resolves the facts about the target from the live account.
  • Each task has a call budget. Over it, the answer is 429.

The answers

OutcomeHTTPBody
Allowed200{ "status": "DECIDED", "decision": { "decision": "ALLOW", "rule_id": "allow-worker-create", ... }, "result": ... }, with the Vultr result
Denied200{ "status": "DECIDED", "decision": { "decision": "DENY", "rule_id": "protect-tagged-destroy", "reason": "...", ... } }, nothing ran
Held200{ "status": "DECIDED", "decision": { "decision": "ESCALATE", ... }, "approval": { "nonce": "..." } }, nothing ran until approved
Malformed400{ "status": "ARGS_INVALID", "errors": [ ... ] }
Bad token401{ "status": "AUTH_TASK_TOKEN_INVALID" }
Over budget429{ "status": "RATE_LIMITED" }

Every decision carries a decision_id that appears in the Ledger, the rule id that decided it, the layers that were consulted, the projected cost, and the model that proposed it.

What your agent should do with each answer

  • ALLOW: continue. The result is in the response.
  • DENY: do not retry the same call. Read the rule id and reason, and change the plan.
  • ESCALATE: stop and wait. A person approves or rejects it, and the approval is re-checked against the live account at that moment.
  • 429 or 401: back off or ask for a new task token. Never fall back to calling Vultr directly: the agent should not hold a credential at all.
