In plain words: a web page can show anything, including this one. So every claim here comes with a check that does not depend on trusting this page. They are listed from easiest to strongest.

Six ways to check it is real

  1. Verify the ledger in your browser (10 seconds). Every verdict is a row in a public ledger, and each row carries a fingerprint of the row before it. The Ledger page downloads all of it and recomputes every fingerprint on your machine. It can also flip one verdict in your copy to show the chain break. Proves: nothing was edited, removed or reordered after it was written, and every server the agent created is tied to the ALLOW decision that authorised it.
  2. Ask the second region directly (10 seconds). The verifier runs on a different machine in a different region (Chicago), with its own address and certificate. The Reconcile page makes your browser ask it directly, with this server out of the request, and shows the Vultr instance id and state it read for prod-db. Proves: an independent host, reading the live Vultr account itself, agrees with this page.
  3. Check the ledger on your own computer (1 minute). 
    curl -sO https://raw.githubusercontent.com/dmustapha/plumbline/main/scripts/verify-ledger.mjs
curl -s https://plumbline.108-61-70-169.sslip.io/api/ledger/public -o ledger.json
node verify-ledger.mjs ledger.json
    The script comes from the public repository on GitHub, has no dependencies and prints one line per check. Proves: the same as the browser check, without running any script this server sent you.
  4. Re-derive every claim (5 minutes). Clone the repository and run npm run verify-claims. It recomputes each claim from the evidence files and the commit they were recorded at. A claim whose code changed after its evidence was taken is withheld, not repeated. Proves: we did not quietly keep a claim after changing the code behind it.
  5. Run it on your own Vultr account. Run it yourself installs the same system on an account you control, so the Vultr console you look at is yours, not ours. Proves: the behaviour holds somewhere we cannot influence.
  6. Watch Vultr's own console. The one view that comes from outside us is the Vultr console for our demo account. That needs our login, so a web page cannot offer it. The demo video shows the console next to a verdict.

What these checks do not prove

A hash chain proves history was not changed after the fact. It does not prove the broker recorded every action truthfully in the first place, because the ledger is the broker's own record. That gap is closed by checks 2 and 6: a second machine reads the live Vultr account with its own key, and compares it with this ledger. If something existed that no ALLOW decision explains, the verifier reports RED.

The verifier has stated limits too: it sees a resource only if it exists at both of its two reads, three seconds apart, and with a view-only key it cannot see firewall groups or Object Storage buckets. The Reconcile page lists them.

If any check on this page ever fails, treat that as the finding. Nothing here is hidden behind the page.
