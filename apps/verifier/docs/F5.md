# F5: verifier contract (internal freeze, G1b -> G1c / G1f / G1h)

Owner: stream G1b. Shapes below are settled; a change needs a note to the integrator. Code: `apps/verifier/src`.

## 1. `POST /lease/renew` (broker -> verifier; public through Caddy, HMAC-signed)

Emitter: `apps/broker/src/lease.ts` (G0, unchanged). Headers: `content-type: application/json`, `x-plumbline-sig`.
Body: `{ "ts": <ms int>, "nonce": "<8..64 chars [A-Za-z0-9]>", "ttl_s": <int 0..PLUMBLINE_LEASE_MAX_TTL_S> }`.
Signature: hex `HMAC-SHA256(lease_secret, "<ts>.<nonce>.<ttl_s>")` (`leaseSignature` in `lease.ts`, identical on both sides).

Checks in order: malformed -> 400 `malformed`; `|now-ts| > 30 s` -> 401 `skew`; bad signature -> 401 `signature`;
`ttl_s > max` (default 120, config bound 1..120; broker default is 120) -> 400 `ttl-too-large` (AG4-VER-2: nothing keeps a lease alive
longer than `max`); nonce already seen -> 401 `replay`; `ts <= last accepted ts` -> 401 `stale-ts` (a captured heartbeat cannot be
replayed after a kill-switch `ttl_s: 0`, even after a verifier restart: the last ts is read back from `lease.json`).
`ttl_s: 0` means "expire now" (kill-switch). Success: 200 `{ "ok": true }`.

### `lease.json` (shared dir, written ONLY by the verifier process)

`{ "last_ts": <broker ms>, "ttl_s": <int>, "received_at": <verifier ms> }`, mode `0640`, owner = verifier user, group = `plumbline-vm2`.
The shared dir must be `root|verifier : plumbline-vm2`, mode `1770` (sticky: the watchdog user, same group, cannot replace or delete
lease.json) and NOT world-accessible. The verifier refuses to boot (`BOOT_REFUSED`) on a world-accessible dir or on a group-writable dir
without the sticky bit.

### Reader API for the watchdog (`apps/verifier/src/lease.ts`, import it, do not re-implement)

```ts
readLease(dir: string, opts?: { uid?: number }): LeaseFile | null
leaseState(l: LeaseFile | null, now: number, ctx?: { startedAt: number; graceMs?: number; everSeen?: boolean }): 'NEVER' | 'ALIVE' | 'LAPSED'
```
- `readLease` returns `null` for: missing file, unparseable JSON, wrong field types, `ttl_s` above the hard bound (300), a symlink, a file
  that is group/world-writable, or (when `opts.uid` is given) a file not owned by that uid. Pass `opts.uid` = the verifier user's uid.
- `leaseState` (AG4-VER-3, fails CLOSED): a valid file is `ALIVE` while `now - received_at <= ttl_s * 1000`, else `LAPSED`; `ttl_s <= 0`
  is `LAPSED`; `received_at` more than 5 s in the future is `LAPSED`. A `null` lease is `NEVER` only during the first-contact grace
  (`now - ctx.startedAt <= graceMs`, default 120 000 ms, and `ctx.everSeen` not true); after the grace, or with no `ctx`, or after the
  caller has ever seen the lease alive, it is `LAPSED`. `NEVER` must NOT disarm the watchdog forever: the watchdog treats `LAPSED`
  as "sweep" and `NEVER` as "grace, do not sweep yet". The watchdog sets `everSeen = true` the first time it reads `ALIVE`.

## 2. Ledger export request (verifier -> broker)

`GET <PLUMBLINE_BROKER_PUBLIC_URL><PLUMBLINE_LEDGER_EXPORT_PATH default /v1/ledger/export>` with headers `x-plumbline-ts: <ms>` and
`x-plumbline-sig: hex HMAC-SHA256(lease_secret, "export.<ts>")` (broker side: `apps/broker/src/ledgerExport.ts`). Response is
`plumbline-ledger-export/v2` (`apps/broker/docs/ledger-export.schema.md`). The verifier fetches it AFTER both live polls (AG4-PRD-7),
verifies it with `verifyExport` (hash chain, freshness 60 s, tie to ALLOW rows) and checks append-only continuity against the last
verified decision it saw (`<stateDir>/ledger-pin.json`).

## 3. `GET /api/verify` and `POST /api/verify/run` (JSON, the verdict card)

`GET` returns the cached last report (never calls Vultr). Before any run: `status: "DEGRADED"`, `codes: ["RECONCILE_DEGRADED"]`,
`detail: "no run yet"`. `POST /api/verify/run` runs now (429 `{status:"RATE_LIMITED"}` with `retry-after: 5` inside 5 s, 409 when a
run is already in flight).

```jsonc
{
  "status": "GREEN" | "RED" | "DEGRADED",
  "codes": ["RECONCILE_RED_UNLOGGED" | "RECONCILE_RED_MISSING" | "RECONCILE_RED_PROTECTED_CHANGED"
          | "RECONCILE_RED_POLICY_VIOLATION" | "RECONCILE_RED_LEDGER_TAMPERED" | "RECONCILE_DEGRADED"],
  "findings": [{ "code": "...", "resource_id": "...", "class": "instance|vpc|registry|", "detail": "..." }],
  "counts": { "live": 0, "baseline": 0, "ledger_rows": 0, "decisions": 0, "allow": 0, "deny": 0, "escalate": 0, "unauthorized": 0, "unknown_outcomes": 0 },
  "polls": [<poll1 start ms>, <poll2 start ms>],      // 3 s apart (never below 3000)
  "polled_twice": true,
  "coverage": ["instance", "vpc", "registry"],
  "not_covered": ["firewall_group ...", "bucket ...", "dollar ceiling / session spend ..."],
  "limits": "point-in-time: a resource created and destroyed between two polls is not seen ...",
  "ledger": { "trust": "fetched" | "pinned" | "unverified", "head": "<hex|null>", "generated_at": <ms|null>,
              "pin": { "seq": <int>, "row_hash": "<hex>" } | null },   // pin = last verified decision, kept in <stateDir>/ledger-pin.json
  "prod_db": { "found": true, "id": "...", "label": "plumbline-prod-db", "status": "active", "power_status": "running",
               "plan": "...", "region": "...", "os": "...", "read_at": <ms>, "read_by": "<verifier hostname>" }   // or { "found": false, ... }
  "notes": ["..."],                                   // e.g. a rejected watchdog log, weak mode
  "verifier_host": "<hostname>",
  "generated_at": <ms>
}
```
`GREEN` is only ever returned when both polls, the export (verified), the baseline manifest and the floor were all available and no
finding survived in both polls. `prod_db` is the verifier host's OWN read of `plumbline-prod-db` from the live list (E-2); the playground
is a VPC, which is part of the live-list compare.

## 4. Files the watchdog (G1c) shares with the verifier (in the shared dir)

- `watchdog-actions.jsonl` (written by the watchdog, read by the verifier): one JSON object per line
  `{ "act": "destroyed", "id": "<vultr id>", "class": "instance|firewall_group", "ts": <ms> }`. The verifier ignores the WHOLE file if it
  is a symlink, world-writable, or (when `PLUMBLINE_WATCHDOG_UID` is set) not owned by that uid, and it excuses a missing resource
  only for an entry whose `ts` is at or after the resource's ALLOW row `created_at_ms` (AG4-VER-4). Create it `0644|0640`, owner watchdog.
- `watchdog-status.json` (watchdog -> served as `/api/watchdog`): free-form object with a `status` string.
- `last-verify.json` (verifier -> anyone in the group): the last report, mode 0640.

## 5. Baseline manifest (`PLUMBLINE_BASELINE_PATH`, written by bootstrap-range over SSH, root-owned, broker cannot edit)

```json
{ "generated_at": <ms>, "resources": [ { "id": "...", "class": "instance|vpc|registry", "label": "...", "plan": "vc2-1c-1gb|start_up|\"\"", "region": "...",
                   "power_status": "running", "os": "Debian 12 x64 (bookworm)", "os_id": 2136, "tags": [] } ] }
```
`power_status` and `os` are REQUIRED for `class: "instance"` entries (CO-2 H-3): an instance entry without them makes the verdict
`DEGRADED`. Must include the broker VM, the verifier VM, `plumbline-prod-db` and the registry `plumblinereg` (H-1; the registry also has a
bootstrap ALLOW row in the ledger). A missing, unparseable or empty file is `DEGRADED`, never GREEN (AG4-VER-8).

Extra keys (os_id, tags, generated_at) are ignored. `plan` is compared exactly except when the baseline plan is `""` (then any plan
passes). The live registry reports plan `start_up`, a VPC reports `""`. Baseline resources are exempt from the E-1 policy re-run
(the owner-created infra rows carry owner requests the floor would refuse) and are compared to the baseline instead.

## 6. Watchdog-side config knobs (G1c reads `loadWatchdogConfig` in `apps/verifier/src/config.ts`)

`verifierUid` (`PLUMBLINE_VERIFIER_UID`, pass to `readLease(dir, { uid })`) and `leaseGraceMs` (`PLUMBLINE_LEASE_GRACE_S`, default 120 s,
pass to `leaseState(l, now, { startedAt, graceMs, everSeen })`). `config.ts` is G1b's; ask for further fields through
`evidence/change-requests.md`.

## 7. Where things are served

The verifier's own origin (`PLUMBLINE_VERIFIER_HOST_PUBLIC`, `ops/Caddyfile.verifier`) serves ONLY `/healthz`, `/api/verify`,
`/api/verify/run`, `/api/watchdog`, `/lease/renew`; `/api/*` carries `access-control-allow-origin: *` so `verify.html` (served by
range-api) can fetch the verdict cross-origin from the independent host. `verify.html` element ids for G1f's `app.js`: `#vrun` (button),
`#vout` (verdict text), `#vprodout` (the host's own prod-db read), `#trust`; everything else on the page is static text. Use `textContent`.
