## Adaptations (declared up front, not silently)

| Skill default | What this project does instead | Why |
|---|---|---|
| Start a dev server on localhost | **Target is the deployed range on VM1** (https://108-61-70-169.sslip.io) plus **hermetic in-process suites** (`app.inject` with a fake broker) | The product is a deployed range with a broker, a runner and a second-region verifier; there is no single local dev server. Destructive, fuzz and concurrency cases run in-process so they cost nothing and cannot hurt the live account. |
| Phase 5 Contract stress | **SKIPPED: no smart contracts.** The "contract" here is the policy engine. Its boundary-value, reentrancy-style (replayed approval), access-control (tier, production write, cross-session) and overflow-style (ttl, cost, NaN, Infinity) classes are covered in Phases 4, 5.5 and 8.5 | No on-chain component exists (KZ-3 is N/A). |
| Playwright for browser phases | Playwright 1.60 (global install) for the multi-viewport sweep; the devtools-driven Chrome and the user's real Chrome for journeys and network proof | Chrome is a singleton; the sweep needs 5 viewports x 10 pages. |
| Fix all bugs with 3 attempts | Same; fixes to deployed code are rsynced to VM1 and re-measured live | |
| Owner-key operations (live gates) | **Blocked mid-run: Vultr rejects the owner API key from this Mac's current IP (105.127.7.132; allow-listed 105.127.6.61).** Needs the user to re-add the IP. Everything that does not need the owner key still ran. | Standing security rule: ask, do not work around. |

Session limits shape the live work: 2 live sessions per IP and 3 attacks per minute per session, so live attack batches are paced at 21 s and one session is shared.

## Test parameters (global)

- Viewports: 320, 768, 1024, 1440, 1920 px.
- Strings: "", " ", "a", "a"x255, "a"x10000, "🔥💀🎯", `<script>alert(1)</script>`, `'; DROP TABLE--`, "NULL", "undefined", null bytes, RTL text, path traversal in ids.
- Numbers: 0, -1, 0.0001, MAX_SAFE_INTEGER, Infinity, NaN, 1e308, -0.
- Network: offline mid-attack, slow 3G, dropped SSE, injected 5xx and non-JSON bodies.
- Concurrency: 20 parallel attacks on one session, 10 parallel policy writes, 10 parallel session creates, 8 sessions at once.
